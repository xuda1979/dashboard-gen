1 引言
------------------------------------------------------------

1.1 编写目的
  本手册是 dashboard-gen（智能体落地页 / 内部工具只读仪表板生成器）V1.0 的
  用户手册，按照 GB/T 8567-2006《计算机软件文档编制规范》第 6 章「用户手册」
  的要求编写。手册面向软件的使用者（包括运维人员、内部工具开发者与普通用户），
  说明软件的安装、启动、日常操作、参数配置及常见问题处理方法，帮助用户快速
  上手并正确使用软件。本手册描述以 V1.0 版为准。

1.2 软件范围
  dashboard-gen 是一款命令行工具软件：用户编写 YAML 或 JSON 格式的页面描述
  文件（DSL），工具将其编译为单个自包含的 HTML 页面。生成的页面内联 CSS 与
  SVG 图表运行时，不依赖任何外部 CDN 或图表库，可离线打开、便于部署。软件
  提供四个命令行子命令（new/build/watch/serve），并自动生成可访问性友好的
  页面结构与 GitHub Pages 部署工作流。

  软件限制：生成页面为只读静态页面，不含交互式后端逻辑、表单提交或账户体系。

1.3 术语与缩略语
  DSL         领域特定语言。本手册中指描述页面结构的 YAML/JSON 文档。
  dg          dashboard-gen 与命令的通用简称（如 dg build）。
  DSO         页面描述文件（如 dg.dsl.yaml、site.yaml），即 DSL 源文件。
  layout      页面布局：hero / grid / sidebar / section / landing 五种。
  component   页面组件：headline、paragraph、list、steps、button、link、
              card、stat、stat-list、toc、badge、divider、quote、code、
              callout、kv、grid、table、chart、image、details、tabs、
              checklist、footnote、timeline、def-list、stepper、sparkline、
              status、heatmap、progress、terminal、gauge、breadcrumbs 共 34 种。
  fetch       图表数据在页面打开时从指定 URL 只读拉取的机制。
  fixture     构建时被复制到产物旁的静态数据文件（如 market.json）。

2 安装与卸载
------------------------------------------------------------

2.1 环境要求
  a) 运行 Node.js v22.0.0 或更高版本（建议 v22 LTS+），内置 npm；
  b) 支持 Linux / macOS / Windows 操作系统（命令行环境）；
  c) 浏览器端无特殊要求：产物的查看仅需现代浏览器
     （Chrome / Edge / Firefox / Safari）。

2.2 软件安装
  方式一：本地安装（推荐）
    cd 到项目根目录（包含 package.json 的位置）后执行：
        npm install
    安装完成后，本机即可通过 npx 调用：
        npx dg --help
  方式二：全局链接安装
        npm link
    之后可直接在任意目录使用 dg 命令：
        dg --help
  方式三：作为模板依赖
    由 dg new 脚手架创建的项目会自动在其 package.json 中声明
    dependencies: { "dashboard-gen": "*" }，执行 npm install 即安装。

2.3 验证安装
  执行下列命令，若能显示出软件帮助信息（Usage: dg new …）即安装成功：
        dg --help

2.4 卸载软件
  全局链接安装的，撤销链接：
        npm unlink
  本地安装的，删除 node_modules 中的相关目录或清除整个项目依赖：
        rm -rf node_modules
  （若曾全局安装 npm 包，可执行 npm uninstall -g dashboard-gen 卸载。）

3 操作说明（按功能模块）
------------------------------------------------------------

3.1 新建一个站点（dg new）
  用途：从内置模板脚手架一个新项目。
  命令格式：
        dg new <name> [--template=<t>]
  参数：
        name        项目目录名称（如 my-site）；
        --template  模板名，可选 landing / table / chart / dashboard /
                    fetch，缺省为 landing。
  示例：
        dg new my-site --template=dashboard
  执行后将在 ./my-site 下生成：
        dg.dsl.yaml           页面 DSL 源文件（模板内容）
        package.json          构建脚本（build/serve）
        .github/workflows/pages.yml   GitHub Pages 自动部署工作流
        market.json           （仅 fetch 模板）数据 fixture
  然后进入项目目录：
        cd my-site

3.2 构建页面（dg build）
  用途：把 DSL 源文件编译为单文件静态 HTML。
  命令格式：
        dg build [src]
  说明：
        src 指 DSL 文件路径；省略时自动查找 dg.dsl.yaml / dg.dsl.yml /
        dg.dsl.json / site.yaml，找到第一个即用之。
  示例：
        dg build dg.dsl.yaml
  输出：
        dist/<name>.html   —— 单文件自包含页面（无 CDN 依赖）
  附加行为：
        若 DSL 中图表以相对路径或 self:// 引用本地 fixture（如
        data: { fetch: market.json }），构建时自动把该文件复制到
        dist/ 下，保证页面打开即可取到数据。

3.3 监听重建（dg watch）
  用途：构建页面，随后持续监听 DSL 源文件的修改，文件变化时自动重新构建，
  适合编辑 DSL 时实时预览。
  命令格式：
        dg watch [src]
  说明：
        监听目录为源文件所在目录；编辑器「另存为/替换保存」触发的
        rename/delete+create 事件也会被识别。
  退出：
        按 Ctrl+C 终止监听并退出。

3.4 本地预览（dg serve）
  用途：启动一个本地静态文件服务，用于预览产物；默认服务 dist/ 目录。
  命令格式：
        dg serve [dir]    （dir 缺省为 dist）
  网址：
        http://localhost:4173
  端口：
        读取环境变量 PORT，缺省为 4173；例如 PORT=8080 dg serve。
  安全性：
        内置路径穿越防护——请求路径含 .. 或 %2e%2e 时返回 403，非法
        百分号编码返回 400，路径经归一化后必须仍在服务目录内。

3.5 页面查看与使用
  生成页面为只读静态页面，打开方式：
  a) 双击 dist/xx.html 直接以浏览器打开（内嵌脚本生效，图表本地绘制）；
  b) 或经 dg serve 以 http://localhost:4173/xx.html 访问；
  c) 或部署到 GitHub Pages / Netlify / nginx 等任意静态服务器。
  页面内图表在打开时依据 window.__DG_DATA__ 内嵌数据绘制；若 DSL 声明了
  data.fetch，则页面打开时向该 URL 发起只读请求，跨域场景需服务器允许 CORS。

3.6 编写 DSL（页面内容定制）
  页面 DSL 是 YAML（或 JSON）映射，根级字段：
        title         页面标题（字符串）
        description   页面描述（字符串）
        layout        布局：hero / grid / sidebar / section / landing
        theme         主题令牌映射：如 accent:"#0ea5e9"、radius:"6px"
        hero          页面头部热区组件列表，或 { content: [...] }
        nav           全局导航：[{ label, href }]
        sections      页面分节：[{ title, nav?, hero?, content: [...] }]
  组件通用写法：
        - type: headline
          level: 1
          text: Ops Console
  常用组件字段示例：
        stat    label/value/prefix/suffix/delta({value,tone})/progress
        chart   kind(line|bar|pie)/title/caption/data|file|fetch/start
        table   rows(数组套数组或对象数组)/caption/header
        card    title/text/intent(primary|success|danger|warning)
  修改 DSL 后执行 dg build 重新生成页面，或使用 dg watch 自动重建。

3.7 可访问性自检（scripts/a11y-check.mjs）
  用途：对生成产物做静态可访问性检查。
  命令：
        node scripts/a11y-check.mjs dist/index.html
  检查项（节选）：跳过链接、lang、唯一 main 地标、nav 标签、表格
  scope="col"/"row"、图表 role="img" 与 aria-label 等；任一缺失将以
  非零退出码报告。

3.8 GitHub Pages 自动部署
  项目内的 .github/workflows/pages.yml 会在推送到 main/master 时自动：
  (1) 安装依赖；(2) dg build 构建；(3) 上传 dist 产物；(4) 部署到 Pages。
  仓库启用步骤：Settings → Pages → Source 选择 GitHub Actions。

4 配置与参数
------------------------------------------------------------

4.1 环境变量
  PORT         dg serve 监听端口，缺省 4173。
  DG_OUTPUT    dg build 输出文件名覆盖，缺省 <name>.html。
               例：DG_OUTPUT=index.html dg build。

4.2 命令行参数汇总
  dg help / dg --help / dg -h    显示帮助信息。
  dg new <name> [--template=<t>] 新建项目（模板白名单见 3.1）。
  dg build [src]                 构建到 dist/<name>.html。
  dg watch [src]                 监听构建。
  dg serve [dir]                 本地静态服务。
  说明：支持 --flag value 与 -f value 两种形式（parseArgs）。

4.3 DSL 配置项（主题令牌）
  theme:
    accent      强调色（十六进制，如 "#0ea5e9"）
    radius      圆角（如 "6px"）
  （其余令牌沿用默认值；深色模式由浏览器 prefers-color-scheme 自动适配。）

4.4 图表数据来源配置
  A. 内嵌数组：data: [ [标签, 值...], ... ]（首行可作为类别/系列名）
  B. 内嵌 CSV ：data: { csv: "a,b\n1,2" }
  C. 内嵌 JSON：data: { json: [...] }
  D. 构建期文件：file: data.csv / file: data.json
  E. 运行期拉取：data: { fetch: market.json } 或绝对 http(s) URL、
                 相对路径与 self://<path> 均支持；同主机需 CORS 放行。
  pie 图特例：data 可为单行多键（每系列切一片）或多行 {label,value}。

4.5 模板列表
  landing（宣传落地页）、table（数据表）、chart（图表示例）、
  dashboard（仪表板：stat KPI + 图表 + 卡片）、fetch（运行时拉取数据）。
  通过 dg new --template=等指定。

5 故障处理与 FAQ
------------------------------------------------------------

5.1 常见故障与解决方法
  F1  执行 dg 提示命令不存在。
       → 未安装或未链接。在项目根执行 npm install 后改用 npx dg；
         或先 npm link 再使用 dg。

  F2  dg build 报错：No DSL file given / DSL file not found。
       → 未指定 src，且当前目录未找到 dg.dsl.yaml / site.yaml 等默认
         文件。请传入 DSL 路径，或在项目目录运行。

  F3  dg build 报 DSL 语法错误（YAML/JSON parse error）。
       → 检查 DSL 缩进、冒号与引号；JSON 文件需以 { 或 [ 起始。错误
         消息含所在文件名。可先 dg watch 借助持续构建快速定位。

  F4  生成页面打开后图表区域显示 No data to draw。
       → 常见原因：a) 内嵌数据为空或结构不符合；b) fetch 数据未复制
         到产物同目录（本地 fixture 需重新 dg build 复制）；
         c) 远程 fetch 被 CORS 拦截。请核对数据源格式并重建。

  F5  dg serve 打开页面无图表/白屏。
       → 页面左上角若显示 404 说明请求了不存在的资源；按
         http://localhost:4173/<name>.html 访问正确路径；确认已
         dg build 生成产物。

  F6  dg serve 返回 400 / 403。
       → 403 为拒绝路径穿越请求（含 .. 或 %2e%2e）；400 为无效 URL
         编码。属安全防护正常行为，请检查访问路径。

  F7  远程 fetch 数据加载失败。
       → 服务端须允许 CORS（Access-Control-Allow-Origin）。本软件
         产物严格只读，无法绕过；建议把 JSON 放在同源路径。

  F8  页面在 dg build 后未更新。
       → 请确认编辑的是已被引用的源文件；或改用 dg watch 实时重建；
         确认输出文件名（DG_OUTPUT 是否覆盖）。

  F9  快捷键/跳转不可用。
       → 页面含 skip-link（键盘 Tab 聚焦可跳出导航直达 main）；确认
         浏览器未屏蔽脚本；产物无 JS 时图表显示 noscript 提示。

5.2 常见问题（FAQ）
  Q1  生成的页面必须联网吗？
      A1  不需要。除 DSL 显式声明 data.fetch 运行期拉取外，页面完全
          离线可用（CSS、SVG 图表运行时、数据全部内嵌）。
  Q2  支持哪些图表类型？
      A2  line（折线）/ bar（条形）/ pie（饼图），均由本地运行时绘制
          SVG，无需图表库。
  Q3  能否用于生产环境？
      A3  可以。产物为标准静态文件，可部署到任意静态托管；页面只读、
          无数据库、无后端，适合内网监控大盘与内部工具页。
  Q4  dashboard-gen 与 LLM 建站产品（Lovable 等）有何区别？
      A4  本软件生成纯声明式、可审计、离线自包含的静态页面，可在高
          权限内网环境安全运行；不支持在线交互编辑，属刻意取舍。
  Q5  支持深色模式吗？
      A5  支持。页面 CSS 令牌含深色媒体查询，随浏览器系统主题自动切换。
  Q6  如何保证生成页面的可访问性？
      A6  生成器自动输出 skip-link、语义化地标与表格、图表 role="img"
          及 aria-label，并附 a11y-check.mjs 静态检查脚本（见 3.7）。
  Q7  部署到 GitHub Pages 需要哪些步骤？
      A7  仓库开启 Pages 并选择 GitHub Actions 部署源即可；项目内
          .github/workflows/pages.yml 已自动配置构建与发布（见 3.8）。
